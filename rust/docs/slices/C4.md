## Goal

A black-box oracle: the TypeScript `pi` at a pinned commit, driven over RPC against a scripted provider, produces
goldens that the Rust `pi` must reproduce. This slice builds the server, the driver, the normalizer, the golden
store and the first twelve scenarios, and verifies the pipeline on the TS side only (the Rust `pi` does not exist
yet; the driver's `compare` subcommand runs against goldens and will be used from C12).

## `pi-fake-provider` (lib + bin)

- An `axum` server with endpoints `POST /v1/messages` (anthropic-messages SSE) and `POST /v1/chat/completions`
  (openai-completions SSE); `/responses` reserved. It serves a **scenario script**: a JSON file listing responses in
  order; each response is `{ content: [text | thinking | toolCall blocks], stopReason, usage?, delayMs?, chunking?: { tokens: n } | { bytes: n }, error?: { status, body, retryAfter? } }`.
  The server renders a response as the provider's exact SSE event sequence (message_start, content_block_start,
  content_block_delta with text_delta/thinking_delta/input_json_delta, content_block_stop, message_delta with usage
  and stop_reason, message_stop; and the OpenAI chunk equivalents) with deterministic chunk boundaries, so both
  implementations see the same bytes. It records every request (`url`, headers, body) to `requests.jsonl` in its
  output dir. No dependency on `pi-ai`.
- CLI: `pi-fake-provider --script scenario.json --out dir --port 0` prints the chosen port on stdout as the first
  line; the lib exposes `start(script, out) -> (addr, handle)` for in-process use.

## `pi-difftest` (bin)

- Scenario layout: `rust/tools/pi-difftest/scenarios/<name>/{scenario.json, commands.jsonl, provider.json, workspace/}`.
  `commands.jsonl` is the RPC stdin, one record per line, with two driver-only records: `{"$wait": "agent_settled"}`
  (consume events until that event) and `{"$sleep": ms}`. `workspace/` is copied to a temp cwd. `scenario.json`
  names the API (`anthropic-messages` or `openai-completions`), the CLI args, and which artefacts to compare.
- Setup per run: a temp `agentDir` with `settings.json` (no telemetry, no update check), `models.json` declaring a
  provider `fake` with `baseUrl` at the server and `api` as the scenario says, `auth.json` with an API key for
  `fake`; `PI_CODING_AGENT_DIR` points at it; env strips `ANTHROPIC_API_KEY` and friends; the `pi` under test runs
  with `--mode rpc --provider fake --model <id>` plus the scenario args.
- Subcommands: `ts-run <scenario>` (runs `node <repo>/packages/coding-agent/dist/cli.js`), `rust-run <scenario>`
  (runs the binary given by `--pi`), `regen [--all | scenario]` (runs TS and writes goldens), `compare [--all | scenario] --pi <path>`
  (runs Rust, normalizes, diffs against goldens, exit 1 on any diff with a readable unified diff), `live` (runs
  both and diffs them directly).
- Artefacts per run, after normalization: `events.jsonl` (all stdout records), `session.jsonl` (the session file,
  if any), `requests.jsonl` (from the server), `fs.json` (sorted listing of the temp cwd with sha256 per file),
  `exit.json` (exit code, stderr tail). Normalizer: UUIDs, 8-hex entry ids (mapped to stable `id-1`, `id-2`, ...
  in order of first appearance), ISO timestamps, epoch-ms fields named `timestamp`, `durationMs`, `delayMs` when
  jittered, temp paths, `version` strings, `responseId`, `user-agent`; the mapping is applied consistently across
  all artefacts of one run so cross-references survive.
- Golden store: `rust/tools/pi-difftest/golden/<scenario>/` plus `META.json` (TS commit sha, node version,
  date). `TS_PIN` holds the sha; `regen.sh` creates `git worktree add /tmp/pi-ts-pin <sha>`, runs
  `npm ci --ignore-scripts`, `npm run hydrate:model-data` is NOT needed (the fake provider is in models.json), then
  `npm run build:offline` (requires hydrated data: run `npm run hydrate:model-data` first and say so in the
  README), then `regen`. `TS_PIN` starts at `085c84e98e7f4c950f2be606466fff4f75d8fe7c`.

## Scenarios (first twelve)

`text-reply`, `tool-bash`, `tool-read-edit-write` (workspace with a file), `multi-turn` (two prompts), `steer`
(prompt, then steer while streaming with `chunking` slow enough), `follow-up`, `abort-mid-stream`, `retry-429`
(one 429 with retry-after then success), `overflow-auto-compaction` (a context-overflow error body then a
compaction summary response then success), `manual-compact`, `thinking-blocks`, `resume-session` (two runs: the
second with `--session <file>` continuing). Each scenario's `commands.jsonl` ends with the session commands that
read state (`get_state`, `get_messages`, `get_session_stats`, `get_tree`) so responses are golden too.

## Acceptance

- `regen --all` from a clean state succeeds; a second `regen --all` produces zero diff (determinism).
- `compare --all --pi <ts shim>` where the shim is a script that runs the TS pi passes (the driver is validated
  against itself).
- `rust/tools/pi-difftest/README.md` documents the scenario format, the normalizer rules, and how to add a
  scenario. `rust/docs/difftest.md` is a short pointer to it.
- `cargo test -p pi-fake-provider` covers the SSE renderers with inline expected bodies for each block type and
  chunking mode.
