# Slice C15a: `pi-tui` I: terminal, keys, keybindings, stdin buffer, width, colors, layout

## Goal

The terminal layer of the TUI with no rendering yet: raw mode and protocol negotiation, the key parser with its
full corpus, keybinding tables, the stdin splitter, the width function, colours and the flex layout. Everything a
renderer (C15b) and the SDK's UI types (C6b) build on. `pi-tui` has no workspace dependency except `pi-json`.

## Deliverables (`pi-tui/src/`)

- `terminal.rs`: the `Terminal` trait (write, size, raw mode, input stream, title, program status, cursor queries,
  colour queries) and `ProcessTerminal` over `rustix` (termios, winsize, SIGWINCH via tokio signal) and
  `windows-sys` (console modes, VT input); Kitty keyboard protocol query and push/pop (`CSI ? u`, `CSI > flags u`,
  `CSI < u`), `modifyOtherKeys` fallback, bracketed paste, mouse modes, synchronized output markers, the escape
  timeout and `drain_input`, the Apple Terminal Shift+Enter fix-up hook (modifier state is platform code: provide
  a `ModifierState` trait with a no-op default and the macOS implementation behind `cfg(target_os = "macos")` using
  `objc2`/`core-graphics` only if it stays small; otherwise Carry-over to C23), terminal capability detection from
  the environment exactly as `terminal.ts` and `terminal-image.ts` do it for colour and hyperlinks (`PI_TRUE_COLOR`,
  `PI_HYPERLINKS`; image protocol detection is C16a).
- `keys.rs`: `parse_key`, `matches_key`, `KeyId` (validated newtype shared with C6a: define it here and have
  `pi-sdk` re-export it), `decode_kitty_printable`, press/repeat/release, legacy sequences and CSI-u, every
  table and special case of `keys.ts`.
- `keybindings.rs`: `TUI_KEYBINDINGS` (ids, default keys, descriptions), `KeybindingsManager` (user overrides,
  conflict detection, `get_keys`, `matches`), the `KeybindingsConfig` JSON shape.
- `stdin_buffer.rs`: splitting raw input into complete escape sequences and paste blocks with the same timeouts.
- `width.rs`: `visible_width` with the ASCII fast path, grapheme segmentation (`unicode-segmentation`), east-asian
  width (`unicode-width` per code point, matching the TS `get-east-asian-width` table: record both Unicode data
  versions in the file comment), the regional-indicator, VS16, ZWJ and tab rules of `utils.ts`, the LRU width
  cache; `wrap_text_with_ansi`, `truncate_to_width`, `slice_by_column`, `extract_ansi_code`, OSC 8 link lookup,
  the CJK break and punctuation rules, `strip_ansi` if `utils.ts` has it.
- `colors.rs`, `oklab.rs`, `terminal_colors.rs`: ports (indexed, sRGB, OKLCH, OKHSL parsing and mixing,
  truecolor and 256-colour output sequences, OSC 10/11/4 reply parsing, colour-scheme reports).
- `layout.rs`, `layout_node.rs`: the flex layout (`basis`, `grow`, `shrink`, `min_size`, `max_size`, `visible`),
  `render_layout_frame` producing lines and boxes for hit testing, scrollbar geometry.
- `program_status.rs`: OSC 7501 program status.
- `lib.rs`: the `Component` trait is NOT in this slice unless C6b has not landed when you start; check
  `rust/crates/pi-tui/src/` first: if `component.rs` exists (C6b), extend nothing there; if not, add the minimal
  `Component` trait from C6b's spec so `layout` can reference it, and say so.

Dependencies expected (exact pins, `workspace = true`): `rustix` (termios, process, stdio), `windows-sys` (the
console features only), `unicode-segmentation`, `unicode-width`, `tokio` (signal, io for the input stream),
`bytes`; justify each.

## Fixture corpora (generated from TS, committed with their scripts under `rust/fixtures/tui/`)

- `keys.jsonl`: every input sequence appearing in `packages/tui/test/keys*.test.ts` and `input*.test.ts`, plus a
  generated set: all CSI-u encodings of printable ASCII and the named keys with every modifier combination, the
  legacy sequences of `keys.ts`'s tables, press/repeat/release variants; record `{ input, parsed }` with the TS
  `parseKey` result (as JSON) and `{ input, id, matches }` for `matchesKey` on 200 random (sequence, id) pairs.
- `width.jsonl`: 5,000 strings mixing ASCII, CJK, emoji (with VS16, ZWJ sequences, flags), combining marks, tabs,
  ANSI/OSC/APC sequences; `{ text, width }` from the TS `visibleWidth`, plus 500 `wrapTextWithAnsi` and
  `truncateToWidth` cases with widths.
- `colors.jsonl`: 500 colour strings (hex, oklch(), okhsl(), indices, mixes) with the TS output sequences for
  truecolor and 256-colour modes.
The generator runs the TS with `node` (type stripping; `packages/tui/src` imports `get-east-asian-width` and
`marked`: run `npm ci --ignore-scripts` at the worktree root first and say so). Rust tests assert exact equality
on every record; a width mismatch class caused by Unicode data version drift is reported with its count and a
Carry-over entry, not silenced.

## Acceptance

- All three corpora pass exactly (or the width drift is listed with counts); the TS tests named above ported case
  by case against a `MockTerminal` (port of `virtual-terminal.ts`'s terminal side without xterm; the screen
  emulator for rendering tests is C15b with `vt100`).
- Raw-mode and negotiation output sequences asserted byte-exact in tests against a recording terminal: enter,
  leave, Kitty push/pop, bracketed paste on/off, mouse on/off, title, program status.
- `cargo doc -p pi-tui` clean.
