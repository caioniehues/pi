# Slice C5: `pi-agent`

Read first: `rust/docs/conventions.md`, `rust/docs/slices.md`, `pi-types` and `pi-ai` docs (C1, C3a).
TS references, read in full: `packages/agent/README.md`, `packages/agent/src/{types,agent-loop,agent,proxy,stream-fn,index}.ts`,

`packages/agent/examples/mcp-codemode/*.ts` (for how callers use it).

## Goal

The agent loop and the `Agent` state object with identical event order, queue semantics and tool execution rules.

## Deliverables

- `types.rs`: `StreamFn` (a boxed async fn or trait object over `Models::stream_simple`'s shape),
  `ToolExecutionMode`, `QueueMode`, `AgentToolCall`, `BeforeToolCallResult`, `AfterToolCallResult`, the contexts,
  `AgentTurnDecision`, `FinishTurn`, `PrepareRequest`, `PrepareNextTurn`, `AgentLoopConfig` (callbacks as boxed
  `Send + Sync` closures or small traits; one struct, all optional fields explicit), `AgentState`, `AgentToolResult`,
  `AgentToolCallOutcome`, `AgentTool` trait (`name`, `label`, `description`, `parameters`, `prepare_arguments`,
  `output_schema`, `execute(id, params, cancel, on_update)`, `replay`, `execution_mode`), `AgentContext`,
  `DEFAULT_AGENT_IDENTITY`.
- `agent_loop.rs`: `agent_loop`, `agent_loop_continue`, `run_agent_loop`, `run_agent_loop_continue`,
  `run_tool_call` with `ToolCallHooks`, the outer follow-up loop and inner tool/steering loop, `declareToolChanges`
  as system messages, `length` stop failing every tool call, parallel and sequential execution, early termination
  when every result sets `terminate`, abort handling, `AgentEvent` emission through an `AgentEventSink` trait.
- `agent.rs`: `Agent` with `subscribe`, `state`, `steer`, `follow_up`, queue helpers and modes, `abort`,
  `wait_for_idle`, `reset`, `prompt(input, images)`, `continue_run`. Internally an actor task (one owner of the
  state; commands over an mpsc; subscribers called in order from the actor task), the pattern `pi-core`'s
  `AgentSession` will build on; document it in the file comment.
- `proxy.rs`: `stream_proxy` client (POST `/api/stream`, SSE of events without `partial`, rebuilding the partial
  message) and the event types; the server side is not ported (no TS consumer in scope).

## Acceptance

- Every test in `packages/agent/test` ported case by case on the faux provider (`pi-ai` feature `faux`), named
  after the TS test; event order asserted exactly as the TS tests assert it.
- A loom-free but deterministic concurrency test: two tool calls in parallel mode complete in reversed order and
  the results are still recorded in call order as TS does.

None.
