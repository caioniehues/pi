# Slice D1: Durable types, memory storage, the storage conformance suite

Read first: `rust/docs/conventions.md`, `rust/docs/slices.md`, `pi-chord` (D0a, D0b), `pi-types` (C1).
TS references, read in full: `packages/durable/README.md`, `packages/durable/docs/spec.md` sections 1, 2 (records),
3.1-3.2 (document definitions and records), 10 (storage contract), 10.1 (failures), 11.1 (memory), 12 and 13;
`packages/durable/src/{types,ids,errors,entries,documents,truncate,tasks,timers,index}.ts`,
`packages/durable/src/storage/{memory,scan,index}.ts`, `packages/durable/src/testing/{storage-conformance,commit-writes,assertions,runner,types,index}.ts`,
`packages/durable/test/{memory-storage,storage-runtime-boundary}.test.ts`, `test/storage-memory.ts`,
`test/fixtures/*`.

## Goal

Durable's record vocabulary and its storage contract in Rust, proven by the ported conformance suite running
against the memory backend. Every later Durable slice builds on these types; every later backend runs this suite.

## Deliverables (`pi-durable/src/`)

- `types.rs` (split by concept if it passes about 1,000 lines: `types/ids.rs`, `types/records.rs`,
  `types/documents.rs`, `types/tasks.rs`, `types/submissions.rs`, `types/queries.rs`, `types/writes.rs`,
  `types/reports.rs`): `Id<Kind>` newtypes (`ConversationId`, `EntryId`, `TaskId`, `SubmissionId`, `DocumentId`
  as `u64` newtypes with serde as plain numbers), `Seq`, `ROOT_CONVERSATION_ID`, document semantics and
  definitions (`DocDefinition`, `DocFamilyDefinition`, scopes session/conversation/rewindable-conversation/task,
  `CheckpointInfo`, versions and migrations as `Box<dyn Fn>`), `ConversationRecord`, `ContextEdit`,
  `EntryRecord`/`EntryDraft`, `SubmissionRecord` (every variant of the union, tagged as in TS),
  `SubmissionSettlement`, `TaskOutcome`, `TaskState` (all phases), `TaskRecord`, `TaskOwnership`,
  `ConversationOwnership`, `JoinPolicy`, `TaskOptions`, `DocumentRecord`, `DocumentCreate`, `DocumentContent`
  (`base` | `delta` with `pi_chord::delta::Op`), `StoredDocument`, `Page`, `Cursor`, `ScanOrder`, the five
  query types, `DocumentPoint`, `DocumentAddress`, `StorageWrite` (all eight variants), `CommitChange`,
  `CommitPublication`, `CommitResult`, `Report`/`ReportInfo`/`ReportFrom`, `HostCallback`, `SetTimer`.
  JSON names and tags must equal the TS so JSONL and SQLite content written by TS reads back (the serde tests
  below prove it).
- `ids.rs`, `errors.rs` (`ReadAfterWrite`, `StorageRequestError`, `SessionFailed`, `ReadOnlySession`,
  `ConversationBusy`, `ConversationIdle` as `thiserror` variants of `DurableError` with the TS messages),
  `entries.rs` (`define_entry`, the built-in entry kinds), `documents.rs` (`define_doc`, `define_doc_family`,
  `resolve_address`, `address_id`, `document_create`, `check_record_scope`, `check_record_version`,
  `materialize_document`, `materialize_document_value` over `pi_chord::delta::Snapshot`), `truncate.rs`,
  `tasks.rs` (`define_task`: the `TaskDefinition` with phases as a map of boxed async handlers and `abort`;
  the runtime that calls them is D6a), `timers.rs` (`SetTimer`, `native_timer` over tokio, `host_timers`).
- `storage/mod.rs`: the `Storage` trait exactly as spec section 10 (async, `Send + Sync`): `commit(batches,
  receive, ctx)` with the prefix semantics and refusal checks Durable owns (global ids, document actions, copy
  resolution), the keyed lookups, the cursor scans with `scan_start`/`next_cursor`, document reads at a point,
  `close`, `read_only`. `storage/scan.rs`. `storage/memory.rs`: `MemoryStorage` as the reference semantics,
  including `PreparedMemoryCommit` and whatever the TS exposes for tests.
- `testing/storage_conformance.rs`: the 2,099-line suite ported case by case as `pub fn storage_conformance_cases(factory) -> Vec<Case>`
  so each backend's test file runs them (D3 uses it); `testing/commit_writes.rs`, `testing/assertions.rs`,
  `testing/runner.rs`. Behind feature `testing`.

## Acceptance

- Conformance: every case of `createStorageConformance` runs green against `MemoryStorage`; the Rust case names
  equal the TS case names so coverage is checkable by diffing the two lists (commit the list as
  `rust/crates/pi-durable/tests/conformance-cases.txt` generated from the TS by a node script).
- Serde round trips: `rust/fixtures/durable/records/*.json`, generated by a node script from the TS test support
  (`test/session-support.ts`, `test/task-support.ts`, `test/harness-support.ts` build representative records:
  every `SubmissionRecord` variant, every `TaskState`, every `StorageWrite` variant, documents in base and delta
  form), parse into the Rust types and re-serialize byte-identical through `to_js_string`.
- `memory-storage.test.ts` and `storage-runtime-boundary.test.ts` ported.
- `cargo doc -p pi-durable` clean; the crate compiles without the `testing` feature.
