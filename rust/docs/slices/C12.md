# Slice C12: milestone M1, the headless `pi`: arguments, print, JSON and RPC modes

Read first: `rust/docs/conventions.md`, `rust/docs/slices.md`, `rust/tools/pi-difftest/README.md` (C4),
`pi-core` (C7-C11), `pi-sdk` (C6). TS references, read in full: `packages/coding-agent/src/{cli,main,rpc-entry}.ts`,
`src/cli/{args,setup,file-processor,initial-message,list-models,credential-print,project-trust}.ts` (the
selector/picker/startup-ui files are C18a; read them to know what this slice must stub for non-interactive modes),
`src/modes/{print-mode,json-event}.ts`, `src/modes/rpc/{rpc-mode,rpc-types,rpc-client,jsonl}.ts`,
`src/core/{output-guard,crash-log,diagnostics}.ts`, `src/extensions/index.ts` (how built-ins are wired),
`docs/cli.md`, `docs/cli-integration.md`, `docs/json.md`, `docs/rpc.md`, `docs/rpc-commands.md`,
`docs/rpc-extension-ui.md`, `docs/environment-variables.md`, and the tests under Acceptance.

## Goal

A `pi` binary a script or an IDE cannot tell from the TypeScript one in print, JSON and RPC modes: same flags,
same records, same session files, same exit codes.

## Deliverables (`pi-cli/src/`)

- `args.rs`: `Args` and `parse_args` porting `args.ts` exactly (every flag and alias in `docs/cli.md`, `--`,
  `@file` arguments, subcommand detection, extension-registered flags collected at runtime, the same error
  messages and exit codes for invalid combinations), `print_help` with the same text, `is_valid_thinking_level`,
  `normalize_session_name`.
- `main.rs`: the `main()` flow of `main.ts` in order: `--offline`/`PI_OFFLINE`; subcommand dispatch (`auth`,
  `install`/`remove`/`uninstall`/`update`/`list`/`config`, `mcp`: in this slice each prints the TS "not available"
  message if its implementation is a later slice, and the report lists them); `--version`; `--export` (C22:
  stub with a clear message); mode resolution (piped stdin forces print); stdout takeover for protocol modes
  (`output_guard.rs`: everything that is not a protocol record goes to stderr); migrations; session directory and
  session manager creation (`--continue`, `--resume` without a TUI falls back as TS does, `--session`,
  `--session-id`, `--fork`, `--no-session`, `--session-dir`, `--name`); missing cwd and project trust resolution
  for non-interactive modes; `create_agent_session_runtime`; model resolution (`--provider`, `--model`, `--models`,
  `--thinking`, `--api-key`, `--list-models [search]`); piped stdin and `@file` prompts (`file_processor.rs`,
  `initial_message.rs`); dispatch to the mode; orderly shutdown on stdin EOF, SIGTERM and SIGHUP with the
  double-signal rule; `crash_log.rs` writing `crashes.json`; the debug log through `tracing` to
  `<agentDir>/pi-debug.log`; `setup.rs` (`process.title`, `PI_CODING_AGENT=true`, `AI_AGENT=pi`).
- `modes/print.rs`: `run_print_mode` with `PrintModeOptions` for text and json output (`json_event.rs` projection
  from `pi-types`), final-text printing, exit codes.
- `modes/rpc/mod.rs`, `jsonl.rs` (strict LF framing, CR stripped, U+2028/2029 never split; backpressure-aware
  stdout writer), `commands.rs` (every command of `rpc-types.ts` with the response shapes of `docs/rpc-commands.md`,
  including `bash` with `bash_execution_update` events carrying the command id, `export_html` stubbed until C22
  with the TS error text, `get_commands`, `switch_session`/`fork`/`clone`), `extension_ui.rs` (the RPC
  `UiContext`: `extension_ui_request` records for select/confirm/input/editor/notify/setStatus/setWidget/setTitle/
  set_editor_text and `extension_ui_response` correlation; everything else no-op as in TS), `rpc_client.rs`
  (a Rust port of `RpcClient` for tests and for later tooling: spawn, correlate by id, `prompt_and_wait`,
  `wait_for_idle`, typed command methods).
- `builtin_extensions.rs`: the static list of compiled-in extensions; in this slice it is empty apart from a
  placeholder that proves the wiring (the real built-ins arrive in C20 and C21b), and `extensions/*.ts`
  discovered in the agent dir or project `.pi/extensions` print the one-line notice that TypeScript extensions are
  not loaded by this build.
- `list_models.rs`, `credential_print.rs`, `project_trust.rs` (non-interactive decision path).

## Acceptance

- `args.test.ts`, `print-mode.test.ts`, `rpc-jsonl.test.ts`, `rpc-prompt-response-semantics.test.ts`,
  `rpc-client-{clear-queue,clone,process-exit}.test.ts`, `rpc.test.ts` (run against the fake provider instead of
  Anthropic), `stdout-cleanliness.test.ts`, `startup-session-name.test.ts`, `session-file-invalid.test.ts`,
  `session-id-readonly.test.ts`, `test/suite/regressions/{7290-json-stream-linear,7911-json-stream-usage,5868-rpc-unknown-command-id,8337-utf8-bom-parsing,1717-2113-agent-session-event-settlement,2023-queued-slash-command-followup,5080-signal-shutdown-extension-cleanup}.test.ts`
  ported case by case as Rust process tests driving `target/debug/pi`.
- `cargo run -p pi-difftest -- compare --all --pi target/release/pi` passes for every C4 scenario on both
  `anthropic-messages` and `openai-completions`. Any scenario that cannot pass is listed in the report with the
  diff and the reason, and lands as a Carry-over entry under the slice that must fix it; the milestone is not met
  until the list is empty.
- `pi --help` output equals the TS output for a build without extension flags (golden captured from
  `node dist/cli.js --help` at `TS_PIN`).
- `rust/check.sh` builds and smoke-tests the release binary; startup time of `pi --version` and of
  `pi --mode rpc` to the first accepted command is measured and recorded in the report.
