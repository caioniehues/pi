## Goal

Everything `pi` reads and writes under `~/.pi/agent` except sessions, with the same file formats, merge rules,
diagnostics and locking, so a Rust `pi` and a TypeScript `pi` can share one agent directory.

## Deliverables (files in `pi-core/src/`)

- `config.rs`: `APP_NAME`, `CONFIG_DIR_NAME`, `VERSION` (from the crate), the env var names
  (`PI_CODING_AGENT_DIR`, `PI_CODING_AGENT_SESSION_DIR`), every `get_*` path helper of `config.ts`
  (agent dir, themes, models.json, auth.json, settings.json, bin, prompts, sessions, debug log, skills,
  extensions, npm, git, tmp, mcp.json, mcp-auth.json, trust.json, crashes.json), tilde expansion, the share viewer
  URL; a `Paths` struct built once from env and home so tests can inject a directory.
- `paths.rs`, `text.rs`: ports of `utils/paths.ts` (normalize, canonicalize, `paths_equal`, resolve, Unicode-space
  normalization, `get_file_revision`) and the pieces of `utils/text.ts` used here (`strip_bom`).
- `lockfile.rs`: proper-lockfile's protocol: `lock(path, LockOptions { stale, realpath, lockfile_path, retries })`
  returns a guard; acquisition is `mkdir <target>.lock` (target is `realpath(path)` unless `realpath: false`);
  on `EEXIST` read the dir's mtime, if older than `stale` remove it and retry, else fail `ELOCKED`; the guard
  spawns a task touching the mtime every `stale / 2` and detects compromise (mtime not ours, dir gone) calling
  `on_compromised`; release removes the dir. Windows `EPERM` retry as in `auth-storage.ts`. Sync and async
  variants as the TS has (`lock_sync`, `lock`). Default `stale` 10 000 ms.
- `settings.rs` (+ `settings/schema.rs`, `settings/defaults.rs`, `settings/diagnostics.rs`): `SettingsManager`
  with global and project scopes, the merge rules, `FileSettingsStorage` (locked read-modify-write through
  `lockfile`, `realpath: false`), `InMemorySettingsStorage`, tool modifiers (`+name`/`-name`, `DEFAULT_TOOL_NAMES`,
  `apply_tool_modifiers`, `get_tool_list_error`), `CACHE_WARMING_MODES`, every getter/setter the TS exposes,
  diagnostics (unknown keys, type errors, deprecated keys) with the same messages, validation of `settings.json`
  against the schema with `pi-schema`.
- `auth_storage.rs`: `AuthStorage` (`CredentialStore` impl over `auth.json`: `get`, `set`, `remove`, `list`,
  `modify` with the lock, the shared read-state cache keyed by file revision, mode `0600` on create, `0700` dir),
  `FileAuthStorageBackend` (`with_lock`, `with_lock_async` with `stale: 30_000, retries: 0`, custom backoff,
  `on_compromised` behaviour), `ReadOnlyAuthStorage`, `InMemoryAuthStorage`; `runtime_credentials.rs`
  (`RuntimeCredentials`: the non-persistent `--api-key` overlay). `resolve_config_value.rs`: `$ENV`, `${ENV}`,
  `!command` resolution with the cache, `resolve_headers`, `is_configured`, missing env var names.
- `models_store.rs`: `FileModelsStore` (`models-store.json`, same backend and locking) and `InMemoryCodingAgentModelsStore`.
- `model_config.rs`: `models.json` schema (serde structs validated against `schemas/models.schema.json` via
  `pi-schema`), `ModelConfig` snapshot loading with diagnostics. `provider_composer.rs`: `compose_model_provider`
  (built-in provider plus `models.json` overrides plus extension `ProviderConfig`), `validate_extension_provider`,
  `resolve_configured_model_headers`, `resolve_compatibility_request_config`, `configured_request_auth_status`,
  `AuthStatus`. `provider_matching.rs`. `model_runtime.rs`: `ModelRuntime` (implements `pi_ai::Models`: catalog
  snapshot plus `models.json` plus extension providers plus the models store, credential synchronization with
  `CredentialSynchronizationError`, auth overrides, refresh). `model_registry.rs`: `ModelRegistry` (the sync
  facade used by extensions; implements `pi_sdk::ModelRegistry`). `model_resolver.rs`: `default_model_per_provider`,
  `resolve_model_reference` (exact, fuzzy, `provider/pattern:thinking` syntax, `minimatch`-style globs: port the
  subset of minimatch the TS relies on and test it), `resolve_model_scope_from_models` with diagnostics,
  `resolve_cli_model`, `InitialModelResult`. `virtual_models.rs`: the router state machine over
  `pi_sdk::ExtensionVirtualModel` (state persisted as `pi.virtual-model-state` custom entries is C8/C10b; this
  slice ports the definitions and routing).
- `trust.rs`: `ProjectTrustStore` (`trust.json` with its `.lock`, nearest-parent lookup, `paths_equal` keys on
  Windows), `get_project_trust_options`, `has_trust_requiring_project_resources`, `project_trust.rs`
  (`resolve_project_trusted` decision flow with `AppMode`; the interactive prompt is a callback).
- `keybindings.rs`: `KeybindingsManager` (over `pi_tui::KeybindingsManager` from C6b) loading `keybindings.json`,
  `migrate_keybindings_config`, `use_windows_keybindings` (Windows and WSL defaults), the `KEYBINDINGS` table
  with descriptions, validation against `schemas/keybindings.schema.json`.
- `migrations.rs`: port of `src/migrations.ts` (legacy `oauth.json`, API keys inside `settings.json`, the old
  `tools/` directory, `commands/` to `prompts`, sessions at the agent root), idempotent, with the same messages.

## Acceptance

- Port case by case: `config.test.ts`, `settings-manager.test.ts`, `settings-manager-bug.test.ts`,
  `settings-manager-compaction.test.ts`, `settings-diagnostics.test.ts`, `auth-storage.test.ts`, `auth-check.test.ts`,

  `config-value-migration.test.ts`, `model-registry.test.ts`, `model-resolver.test.ts`, `model-runtime-*.test.ts`,
  `model-catalog-refresh.test.ts`, `trust-manager.test.ts`, `project-trust-saved-decision.test.ts`,
  `keybindings.test.ts`, `keybindings-migration.test.ts`, `windows-shell-config.test.ts` (keybinding parts),
  `test/migrations*.test.ts` if present.
- Lock interop: `rust/crates/pi-core/tests/lock_interop.rs` spawns `node` with a script using
  `node_modules/proper-lockfile` (resolved from the repo root; the test is skipped with a message when
  `node_modules` is absent) and checks: Rust holds, node fails with `ELOCKED`; node holds, Rust fails; a stale
  lock from either side is taken over by the other after `stale`; mtime refresh keeps a long Rust hold from being
  stolen by node.
- Format round trips: `settings.json`, `auth.json`, `models.json`, `models-store.json`, `keybindings.json`,
  `trust.json` fixtures (write them with the TS code paths in a node script committed under
  `rust/fixtures/config/`, or copy from the TS tests) parse, re-serialize through `to_js_string_pretty(2)` and
  compare byte-for-byte where TS writes with 2-space indentation (check each writer in TS and match it).
- `cargo test -p pi-core` runs without network.
