## Goal

JSON Schema validation (drafts 2020-12 and 7) compiled once into closures, with pi-schema's coercion rules and error
messages, so tool arguments are accepted and rejected exactly as the TypeScript pi does.

## Deliverables

Crate `pi-schema`, files mirroring the TS modules: `types.rs` (`JsonSchema`, `CompileOptions`, `Draft`,
`ValidationError { path, keyword, message }`, `ParseResult`), `compiler.rs` (keyword grouping by constrained type,
the specialized closures for closed objects, single-item arrays, tagged unions and leaves), `checks.rs` (primitive
checks, `deep_equal`), `annotations.rs` (`unevaluatedProperties`/`unevaluatedItems` tracking), `resolver.rs` (`$id`,
`$ref`, `$anchor`, `$dynamicRef`/`$dynamicAnchor`, `$defs`/`definitions`, external `schemas`, `unresolvedRefs`
policy), `explain.rs` (errors produced only after a failed check, memoized for recursive unions, messages equal to
the TS strings), `coerce.rs` (the three passes: TypeBox `Value.Convert` then Ajv `coerceTypes` semantics as the TS
documents them), `builders.rs` (`obj`, `str`, `num`, `int`, `bool`, `nul`, `arr`, `tuple`, `lit`, `union`, `one_of`,
`opt`, `nullable`, `map`, `recursive`, `unknown`, `unsafe_`; they return `JsonSchema` values with the same JSON as
TS; `Static<>` has no Rust equivalent, callers deserialize validated JSON with serde), `validator.rs`
(`Validator`, `CoercingValidator`), `formats/` (all 2020-12 formats plus `url` and `json-pointer-uri-fragment`,
ported from the TypeBox-derived checks, including the IDNA/punycode code for `idn-hostname`), `lib.rs`.

Public API: `compile(schema: &JsonValue, options: CompileOptions) -> Result<Compiled, CompileError>`;
`Compiled::check(&JsonValue) -> bool`, `errors(&JsonValue) -> Vec<ValidationError>`, `validate(&JsonValue) -> Result<(), Vec<ValidationError>>`,
and with `coerce` enabled `coerce(&JsonValue) -> JsonValue` and `parse(&JsonValue) -> ParseResult`.
`CompileOptions { draft, formats: FormatSet, schemas: Vec<JsonValue>, coerce: bool, unresolved_refs: Throw | Reject }`.
The formats are a value you pass (`pi_schema::formats::standard()`), not a global.

Decided differences from TS, each documented in the file comment where it applies:

- The non-JSON value extensions (`bytes`/`Uint8Array`, `bigint`, `undefined`) do not exist: the value model is JSON.
  Their keywords, if present in a schema, reject every value. An optional property set to JSON `null` is NOT absent
  (TS: `undefined` counts as absent; there is no `undefined` in JSON).
- Closures are `Box<dyn Fn(&JsonValue, &mut Ctx) -> bool + Send + Sync>`; compilation allocates, checking does not
  (no per-call allocation on the success path; explain allocates only after a failure).

## Acceptance

- The official suite: a test iterates `packages/schema/test/fixtures/json-schema-test-suite/tests/{draft2020-12,draft7}/**/*.json`
  (optional tests included exactly as `test/suite.ts` includes them), serves the `remotes/` directory under the
  `http://localhost:1234/` ids through `CompileOptions.schemas`, loads the meta-schemas from
  `packages/schema/test/fixtures/meta-schemas/` the way `suite.ts` does, and asserts pass/fail per case. The
  `KNOWN_FAILURES` list is copied verbatim from `conformance.test.ts`; a case that fails outside the list fails the
  test, and a listed case that passes fails the test too (so the list stays exact).
- `coerce.test.ts`, `coerce-typebox.test.ts`, `validator.test.ts`, `builders.test.ts`, `equal.test.ts` ported case by
  case, including every expected error message string.
- Benchmarks are out of scope; a single `#[bench]`-free timing test is not required.
