## Goal

Every data type that crosses a file or a wire, with serde representations that read and write exactly what the
TypeScript implementation reads and writes, and the telemetry contract every later crate instruments against.

## `pi-types`

Files, one concept each: `content.rs` (content blocks), `message.rs` (pi-ai messages), `agent_message.rs`
(`AgentMessage` with coding-agent's custom roles), `usage.rs`, `tool.rs` (`Tool`, `ToolReference`,
`ConstrainedSamplingConfig`), `model.rs` (`Model`, `ImageModel`, `ClassifierModel`, `ModelCost`, `ModelInputLimits`,
thinking levels, `ThinkingLevelMap`, `ModelPromptCache`), `stream_event.rs` (`AssistantMessageEvent`, `StopReason`,
`DeferredHandle`, `AssistantMessageDiagnostic`), `agent_event.rs` (`AgentEvent`), `session_entry.rs` (header and the
11 entry kinds, `SessionTreeNode`, `SessionInfo`), `session_event.rs` (`AgentSessionEvent`, `CompactionResult`),
`json_event.rs` (`JsonAgentSessionEvent` and `to_json_event`), `rpc.rs` (`RpcCommand`, `RpcResponse`,
`RpcSessionState`, `RpcSlashCommand`, extension UI request/response records), `classifier.rs` and `images.rs`
(classifier and image generation types), `lib.rs` re-exporting all of it.

Representation rules (decided; apply uniformly):

- Tagged unions are `enum`s with `#[serde(tag = "type")]` (content blocks, events, entries, RPC records) or
  `#[serde(tag = "role")]` (messages). Variant payloads are structs named after the TS interface.
- A TS field `x?: T` is `Option<T>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`: absent in,
  absent out. A TS field `x: T | null` is `Option<T>` serialized as `null`: `parentId`, `ContextEditEntry.replacement`,
  `BranchSummaryMessage.fromId`, `SystemMessage.sections` values. A TS field `x: T | undefined` (e.g. `LabelEntry.label`,
  `BashExecutionMessage.exitCode`) is omitted when absent. Name every such choice in a comment on the field.
- Integers that are counts, indices or epoch milliseconds are `u64` (`i64` where TS can be negative: exit codes,
  `timestamp` never); money and ratios are `f64`. Serialization goes through `pi_json::to_js_string`, so `100.0`
  still prints as `100`.
- Every struct that is persisted or sent on a wire carries `#[serde(flatten)] pub extra: pi_json::JsonObject` so
  unknown fields round-trip (TS objects may carry fields this port does not know). Enums with a tag get an
  `Other(JsonObject)` fallback variant via an outer `#[serde(untagged)]` wrapper where the tag is unknown, so an
  unknown entry type or event type is kept, not rejected; document the pattern once in `lib.rs` and use it for
  `SessionEntry`, `AgentMessage` and `AgentSessionEvent`.
- Field order in each struct follows the order the TS code writes the object (check the constructors in
  `session-manager.ts`, `agent-loop.ts`, `event-stream.ts`, not the interface declaration), so Rust-written JSON has
  the same key order as TS-written JSON. Where TS has two writers with different orders, pick the persisted one and
  note the other.
- `Model.compat` stays `Option<JsonObject>` in this slice (C3 types it per API). `AgentTool`, `AgentToolResult`,
  `AgentLoopConfig` and everything with callbacks are NOT in `pi-types`; they belong to `pi-agent` (C5).
- `AssistantMessageEvent` carries `partial: AssistantMessage` by value in Rust (the TS shares one mutable object; the
  Rust stream in C3 will decide how to avoid copies; `pi-types` only defines the shape).

`to_json_event` (`json_event.rs`) ports `modes/json-event.ts` exactly: strips `partial`, adds `usage`, adds `id` and
`toolName` to `toolcall_start`.

## `pi-telemetry`

Files: `context.rs` (`TelemetryContext` and `TelemetrySpan` traits, `SpanOptions`, `SpanLink`, `SpanStatus`,
`AttributeValue`, `SpanAttributes`), `metrics.rs` (counter, up-down counter, histogram, `TelemetryMetrics`),
`propagation.rs` (`TelemetryCarrier`, `TelemetryPropagation`), `noop.rs`, `memory.rs` (`InMemoryTelemetryContext`
recording `StoredSpan`/`StoredTrace`/`StoredMetric`, `telemetry_now`), `store.rs` (`TelemetryStore` trait and query
types), `schema.rs` (`TelemetrySchema` as runtime data: span definitions with start/end attributes, events, parent
rules, metric definitions; a `validate_against_schema` used by the conformance suite), `render.rs` (`render_trace`),
`testing/conformance.rs` (the adapter conformance suite as a function taking a factory, mirroring
`createTelemetryAdapterConformance`), `tracing_bridge.rs` (an adapter that forwards spans and events to the `tracing`
crate; optional feature `tracing`).

Rust shape of the contract (decided): `TelemetryContext::start_span(&self, options: SpanOptions) -> Box<dyn TelemetrySpan>`
returns a span that is also a context (it can start children) and ends when `end(self: Box<Self>)` is called or when
it is dropped (drop ends with the current status). `TelemetrySpan` has `add_link`, `add_event`, `set_attributes`,
`set_status`. Everything is `Send + Sync`, object-safe, no generics on the traits; typed schema starters are plain
helper functions, not generic magic. Times are `f64` milliseconds at microsecond resolution as in TS.

## Acceptance

- `packages/coding-agent/test/fixtures/large-session.jsonl` and `before-compaction.jsonl`: every line parses into
  `FileEntry` (header or `SessionEntry`), re-serializes through `to_js_string`, and the re-parsed `JsonValue` equals
  the original line's `JsonValue`. Additionally a test counts the lines that are byte-identical after re-serialization
  and asserts the count against a number you establish and record in the test with the list of reasons for the rest
  (key order from a second TS writer, for example). Fewer than 5 percent of lines may differ.
- Hand-written round-trip tests for every variant of every enum, including an unknown-type entry, an unknown
  message role and a message with extra fields.
- `to_json_event` tests port the cases of `packages/coding-agent/test/json-event*.test.ts` (find them with grep).
- The telemetry conformance suite ported case by case runs green against `InMemoryTelemetryContext` and against
  the noop context where the suite allows; `render.test.ts` goldens reproduced; `metrics.test.ts` and
  `propagation.test.ts` ported.
- `cargo doc -p pi-types -p pi-telemetry` has no warnings; every pub item documented.
