## Goal

The shared session core every mode runs on: one actor owning the conversation state, with pi's exact ordering of
events, queues, hooks and extension handlers.

## Deliverables (`pi-core/src/session/agent_session/`, `pi-core/src/extensions/`, `pi-core/src/resources/`)

- Before coding, write `rust/docs/agent-session-map.md`: every TS method of `AgentSession` mapped to the Rust
  function that ports it (or "C10b" / "C11"), so reviewers can check coverage. Keep it updated in C10b and C11.
- `agent_session/actor.rs`: the actor (`tokio::task` owning `State`, an mpsc of `Command`s each carrying a
  oneshot reply; subscribers invoked synchronously inside the actor in subscription order; extension handlers
  awaited sequentially in registration order on the actor task; tool executions spawned and reported back as
  commands). `AgentSession` is the handle: cheap to clone, every public TS method becomes an async method that
  sends a command. Getters that TS exposes synchronously (`model`, `thinking_level`, `is_streaming`,
  `is_idle`, `messages`, `session_file`, ...) read from an `Arc<RwLock<Snapshot>>` the actor updates after every
  state change, so they stay synchronous.
- `agent_session/run.rs`: `prompt` with `PromptOptions` and `PromptDisposition`, `steer`, `follow_up`,
  `send_user_message`, `clear_queue`, `_start_run`, `_prepare_run`, `_handle_post_agent_run`, before-settle
  boundary, `agent_settled` emission rules, `abort`, `wait_for_idle`, the `BeforeAgentStartTrigger` flow,
  input handlers, extension command dispatch, skill command expansion, prompt template expansion.
- `agent_session/tools.rs`: the tool registry (definitions from built-ins, SDK custom tools, extension tools),
  exposure and activation rules, `allowedToolNames`/`excludedToolNames`, `defaultTools` modifiers,
  `prepare_loadout` and hidden declarations, `set_active_tools_by_name`, `get_all_tools`, `_before_tool_call`
  and `_after_tool_call` (the `tool_call`/`tool_result` hooks with their composition rules), nested tool calls
  (`NestedToolCallRunner`, `NestedCallRecorder`, `NESTED_CALL_LIMITS`), `tool_execution_*` events with
  `parent_tool_call_id`.
- `agent_session/prompt.rs`: `_rebuild_system_prompt`, `_prepare_prompt_and_tool_loadout`, forced prompt
  projection, `_restore_tools_from_transcript`, `get_system_prompt`, `get_system_prompt_options`.
- `agent_session/retry.rs`: auto retry (`_prepare_retry`, `_is_retryable_error`, `abort_retry`, `is_retrying`,
  `auto_retry_enabled`, the `auto_retry_*` events).
- `agent_session/bindings.rs`: `bind_extensions`, `_bind_extension_core` (the `ContextActions` implementation
  for `pi-sdk`), `reload`, `dispose`, `create_replaced_session_context`.
- `extensions/runner.rs`: `ExtensionRunner`: loads built-in and compiled-in extensions (`Vec<Box<dyn Extension>>`
  supplied by the binary), runs `setup` with queued registrations, dispatches every event with the composition
  rules of `runner.ts` (documented per event in `docs/sdk.md` by C6a; implement and test them here), tool and
  command and shortcut and flag registries, renderer registries, UI request routing to the mode's `UiContext`,
  `ExtensionError` reporting, `replaceable` conflict handling, `invalidate` on reload.
- `resources/loader.rs`: `ResourceLoader` trait and `DefaultResourceLoader` (skills, prompts, themes, context
  files `AGENTS.md` and variants with the walk-up and worktree rules, `SYSTEM.md`/`APPEND_SYSTEM.md`, package
  resources via the package manager interface defined here and implemented in C22, collisions and diagnostics,
  reload); `resources/skills.rs` (`SKILL.md` frontmatter, validation, `format_skills_for_prompt`),
  `resources/prompt_templates.rs` (`parse_command_args`, `substitute_args`, `load_prompt_templates`,
  `expand_prompt_template`), `resources/slash_commands.rs`, `resources/system_prompt.rs` (`build_system_prompt*`,
  sections, `diff_system_prompt_sections`), `resources/frontmatter.rs`, `resources/pi_manifest.rs`,
  `resources/source_info.rs`.
- `agent_session_runtime.rs`: `AgentSessionRuntime` (`new_session`, `switch_session`, `fork`, `import_from_jsonl`,
  rebinding), `agent_session_services.rs`, `sdk.rs` (`create_agent_session` and friends: the Rust SDK entry
  points for hosts), `event_bus.rs`, `exec.rs`.
- `testing/harness.rs`: the port of `test/suite/harness.ts` (`create_harness` with faux provider, in-memory
  managers, event recording, `events_of_type`, `set_responses`, test extension factories), behind feature
  `testing`.
